# CLAUDE.md: Agent Garden conventions

> "See every AI agent you run as a living garden: what's thriving, what's wilting, and which one to call."

Agent Garden is a local-first visualizer for a person's AI agent system (agents, harnesses, skills,
loops), built on their own Claude Code data. `PLAN.md` is the source of truth for scope and
milestones. `PROGRESS.md` is the status log. `docs/schema.md` is the trace schema.

## Vocabulary (use exactly these meanings in code, UI copy, and docs)

- **Agent**: a model using tools in a reason, act, observe cycle toward a goal. In Claude Code data:
  the main thread (`main`) or a subagent type (`Explore`, a custom `agents/*.md` definition, ...).
- **Harness**: the environment one agent runs inside: system prompt / CLAUDE.md, allowed tools,
  permissions, MCP servers, available skills, model, effort, context settings. Harnesses are
  versioned (`HarnessVersion`). A lineage of versions is a `HarnessFamily` (rendered as a bed).
- **Skill**: packaged know-how for one task, loaded on demand (SKILL.md).
- **Playbook**: skills chained into required steps with gates (user-declared in `garden.yaml` for v1).
- **Loop**: the system that triggers agents, checks their work, and decides what runs next.
- **Connector / MCP**: access to outside tools and data.
- **Loop tiers** (`LoopTier`): `agent` (seconds), `verification` (minutes), `application` (hours),
  `hill_climbing` (days).
- **Run**: one agent pursuing one goal. Main thread: one human prompt plus all work until the next
  human prompt. Subagent: one invocation. A `Session` is one transcript file and groups runs.
- **Planting**: one agent inside one harness family (one plant in one bed).

Do not invent synonyms ("bot", "worker", "config") for these terms in UI copy.

## The garden mapping rule

Every visual property must encode a real metric someone would act on. No decoration-only encodings.

- All encodings live in one registry (`packages/core/src/encodings.ts`). The legend is generated
  from that registry, so a channel cannot exist without a legend entry.
- The legend is always one click (or the `L` key) away in every view.
- Every encoded number has a "how computed" affordance that shows inputs, formula, and sample size.
- Ambient motion (gentle sway) is allowed only if it carries no meaning and is listed in the legend
  as "ambient, no meaning". Respect `prefers-reduced-motion`.

## Privacy rules (non-negotiable)

- Everything runs locally. No data leaves the machine: no telemetry, no CDN assets (fonts are
  self-hosted), no remote APIs at runtime. The server binds to `127.0.0.1` only.
- Redaction happens at ingestion, before anything touches the store. The store accepts only the
  branded `RedactedText` type, which only `packages/ingest/src/redact` can produce. Do not cast
  around it.
- Values under `env`, `headers`, and similar config maps are always replaced (key names kept).
- By default the store keeps redacted, truncated previews of message and tool content, not full text.
- Never commit real user data. Fixtures are synthetic or generated by `scripts/demo`. If you need
  a real-format example, reduce it to its shape and fake the values.
- `pnpm test` includes the redaction proof test (planted secrets must not appear anywhere in the
  SQLite file bytes). It must pass before any commit that touches ingestion or the store.

## Data-format discipline

- Do not assume file formats or paths. Every parser needs (1) a fixture that reproduces the real
  shape and (2) an entry in `docs/sources.md` saying where and on which version it was verified.
- Parsers are tolerant: unknown record types and fields are counted and reported by
  `garden inspect`, never thrown on.
- Claude Code writes one API response as several JSONL lines that each repeat the full `usage`.
  Dedupe token usage by `message.id`. Never sum `usage` per line.

## Honest metrics

- A success rate is never shown without its `OutcomeEvidence` (which heuristics fired, weights,
  manual overrides, n). Manual labels always win over heuristics, and the UI says when a label is manual.
- Rates with small n show their uncertainty (Wilson interval) and an `n=` label.
- Seasons compares outcomes across harness versions. That is correlation, and the UI says so.
- Cost is computed at query time from tokens and the versioned table in `packages/core/src/pricing.ts`
  (source and date recorded in `docs/sources.md`). Tokens are stored. Dollar amounts are not.

## Repo layout

```
packages/core     schema types, zod validators, view contracts, encodings registry, pricing, heuristics
packages/ingest   adapters (claude-code, ...), redaction, SQLite store, `garden` CLI
packages/router   "which one do I call?" ranking (BM25 + embeddings + outcome weighting)
packages/server   local Hono API on 127.0.0.1 that serves view contracts and the built web app
apps/web          React + Vite shell; PixiJS garden renderer in apps/web/src/garden
scripts/demo      deterministic demo-dataset generator (writes real Claude Code file formats)
fixtures/         small synthetic fixtures for parser and redaction tests
docs/             PRD, schema, sources, demo script
```

## Commands

```
pnpm install
pnpm typecheck        # tsc across workspaces
pnpm lint             # eslint + prettier --check
pnpm test             # vitest (unit + golden + redaction proof)
pnpm garden <cmd>     # CLI: inspect | ingest | label | stats | db:init (serve, export arrive in M3)
pnpm demo:data        # generate the demo dataset into .garden-demo/ and ingest it
# later milestones: pnpm build, pnpm demo (http://127.0.0.1:4310), pnpm e2e (playwright)
```

## Code style

- TypeScript 6.0.x (typescript-eslint does not support 7.x yet), strict, ESM, named exports. No `any`. Use `unknown` plus a zod parse at IO boundaries.
- Heuristics, encodings, and view-model builders are pure functions with unit tests.
- Renderer: imperative PixiJS in `apps/web/src/garden`. React owns DOM chrome (panels, legend,
  router box, tables). Do not put per-frame state in React.
- Colocate tests as `*.test.ts`. Golden fixtures live under `fixtures/`.
- Schema changes update `packages/core/src/schema.ts`, the SQLite migration, and `docs/schema.md`
  in the same commit (`schema-doc.test.ts` enforces the doc). zod is for parsing raw inputs
  (transcript lines, config files, API request bodies), not for internal entities.
- Planted secrets in tests are assembled from fragments at runtime (`redact/planted-secrets.ts`).
  Never write a literal secret-shaped string into the repo.

## Milestone protocol

1. Each milestone in `PLAN.md` lists verification checks. A milestone is done only when all pass:
   tests green, build green, and rendered output checked against the mapping table (Playwright
   screenshot attached to `PROGRESS.md` where a view changed).
2. Log status, evidence, and known gaps in `PROGRESS.md`.
3. Commit per milestone: `M<n>: <summary>`. Record verified external facts in `docs/sources.md`.
